########## ROOT help
Gickers.sh is a self-hostable Git server (inspired by Soft Serve) for the command line. It provides Git repository hosting, fine-grained access control, branch protections, commit signature enforcement, and webhooks driven entirely via SSH, HTTP, and an interactive TUI.

Usage:
  ssh -p 2223 localhost [command]

Available Commands:
  about                Show the server README (About)
  help                 Help about any command
  info                 Show your info
  install              One-shot installer and deployment wizard for gickers.sh
  pubkey               Manage your public keys
  recover              Recover account access with your backup password
  repo                 Manage repositories
  server               Manage host server, status, settings, and updates
  set-username         Set your username
  settings             Manage server settings
  signup               Register yourself as a new user with your SSH key
  token                Manage access tokens
  user                 Manage users
  web                  Authenticate the web interface
  wiki                 Browse and manage the server wiki

Flags:
  -h, --help   help for this command

Examples:
  # Clone a repository over SSH
  git clone ssh -p 2223 localhost/my-repo.git

  # Inspect your user identity and registered SSH keys
  ssh -p 2223 localhost info

  # Browse and manage repositories
  ssh -p 2223 localhost repo list
  ssh -p 2223 localhost repo create my-project --private

  # Manage personal access tokens and public keys
  ssh -p 2223 localhost pubkey list
  ssh -p 2223 localhost token create "ci-pipeline" --expires-in 30d

Wiki:
  Web:  http://localhost:23232/wiki/home
  CLI:  ssh -p 2223 localhost wiki show home
  TUI:  ssh -p 2223 localhost → Wiki → home

Use "ssh -p 2223 localhost [command] --help" for more information about a command.

########## help install
Generates a self-contained one-shot installer & deployment wizard for gickers.sh on your local machine or remote VPS.

Configures domain, Docker CE & Compose stack, OpenSSH transition to port 2222, UFW firewall, systemd service, and PostgreSQL.

Usage:
   install [flags]

Aliases:
  install, installer

Flags:
      --admin-key string        initial admin SSH public key
      --admin-user string       initial admin username
      --allow-keyless bool      allow keyless SSH connections (true/false)
      --allow-signup bool       allow public self-service signup (true/false)
      --anon-access string      anonymous access policy (read-only, no-access, public)
      --app-name string         application branding name
      --bash bool               force Bash installer script
      --db-name string          Postgres database name
      --db-password string      Postgres database password
      --db-user string          Postgres database user
      --dir string              installation directory
      --domain string           target public domain name (FQDN)
      --dry-run bool            simulate deployment without modifying system
  -h, --help                    help for install
      --http-port int           public HTTP port (default: 80)
      --https-port int          public HTTPS port (default: 443)
      --lfs bool                enable Git LFS (true/false)
      --ps1 bool                force PowerShell installer script
      --skip-docker bool        skip Docker CE installation
      --skip-sshd-switch bool   do not switch host OpenSSH port from 22
  -y, --yes bool                non-interactive mode with defaults

Scope:
  Public (all SSH keys and callers).

Examples:
  # One-shot installation & deployment (interactive wizard)
  ssh -p 2223 localhost install | bash            # Linux / macOS
  ssh -p 2223 localhost install | iex             # Windows (PowerShell)

  # Automated non-interactive deployment
  ssh -p 2223 localhost install --domain code.example.com --yes | bash

########## help repo branch protect
Enforces push safeguards on branches matching a glob pattern via the server pre-receive hook. Protects production branches against accidental force-pushes or deletion.

Usage:
   repo branch protect REPOSITORY PATTERN [flags]

Arguments:
  REPOSITORY    Repository name.
  PATTERN       Branch glob pattern (e.g. "main", "release/*", "v*").

Flags:
      --admins-only   only administrators may update matching refs
  -h, --help          help for protect
      --no-delete     reject deletion of matching refs
      --no-force      reject non-fast-forward (force) updates

Scope:
  Repository Admin or Server Admin.

Examples:
  # Protect main branch against force-pushes and deletion
  ssh -p 2223 localhost repo branch protect my-app main --no-force --no-delete

  # Protect all release branches against force-pushes
  ssh -p 2223 localhost repo branch protect my-app "release/*" --no-force

  # Restrict pushes on all branches to administrators only
  ssh -p 2223 localhost repo branch protect my-app "*" --admins-only

########## help repo collab add
Add a collaborator to a repo. LEVEL can be one of: no-access, read-only, read-write, or admin-access. Defaults to read-write.

Usage:
   repo collab add REPOSITORY USERNAME [LEVEL] [flags]

Arguments:
  REPOSITORY    Repository name.
  USERNAME      Username of the collaborator.
  LEVEL         Access level: 'read-only', 'read-write', 'admin-access', or 'no-access' (default: read-write).

Flags:
  -h, --help   help for add

Scope:
  Repository Admin or Server Admin.

Notes:
  - read-only: clone, pull, and inspect repository.
  - read-write: push commits and non-protected branches.
  - admin-access: manage collaborators, branch protection, webhooks, and settings.
  - no-access: revokes all access on private repositories.

Examples:
  # Add a collaborator with default read-write access
  ssh -p 2223 localhost repo collab add my-app bob

  # Add a reviewer with read-only access
  ssh -p 2223 localhost repo collab add my-app charlie read-only
